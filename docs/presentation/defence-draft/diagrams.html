1. Context / კონტექსტი

svg/01-context.svg

EclipsVault is one software system. A vault account in a browser is a person and uses a session. An application that uses a service account is an external system and calls the Public API with an API key. A new account is activated from an invitation link sent by SMTP. The identity provider, SMTP, Vault Transit, and the dynamic-secret target databases exist only when that integration is configured.

EclipsVault ერთი პროგრამული სისტემაა. ბრაუზერში მყოფი საცავის ანგარიში პიროვნებაა და სესიას იყენებს. აპლიკაცია, რომელიც სერვისის ანგარიშს იყენებს, გარე სისტემაა და საჯარო API-ს API გასაღებით იძახებს. ახალი ანგარიში SMTP-ით გაგზავნილი მოწვევის ბმულით აქტიურდება. იდენტობის მომწოდებელი, SMTP, Vault Transit და დინამიკური საიდუმლოების სამიზნე ბაზები მხოლოდ მაშინ არსებობენ, როცა ეს ინტეგრაცია კონფიგურირებულია.

2. Container / კონტეინერი

svg/02-container.svg

The Angular UI, the Web application, and one database are runtime containers. Redis is a fourth container only when it is enabled. The Angular UI runs in the browser, sign-in included, and calls the UI API with the session cookie. The Web application serves the Angular files, the UI API, the Public API, and three server pages of its own. It refuses to start without `Database:Provider`. The person and the external systems stay outside the boundary.

Angular UI, Web აპლიკაცია და ერთი ბაზა გაშვების კონტეინერებია. Redis მეოთხე კონტეინერია მხოლოდ მაშინ, როცა ჩართულია. Angular UI ბრაუზერში ეშვება, შესვლის ჩათვლით, და UI API-ს სესიის ქუქით იძახებს. Web აპლიკაცია Angular-ის ფაილებს, UI API-ს, საჯარო API-ს და საკუთარ სამ სერვერულ გვერდს აწვდის. ის `Database:Provider`-ის გარეშე არ ეშვება. პიროვნება და გარე სისტემები საზღვრის გარეთ რჩებიან.

3. Web component / Web-ის კომპონენტი

svg/03-web-component.svg

`AngularUiRoutes` serves the Angular document only for the paths it lists, the sign-in pages included. A signed-in caller on an unmatched page URL gets the `ServerPage` not-found page. Sign-in calls `AuthController` and `PendingSignInController`, and `SessionIssuer` issues the session only after the second factor. An invitation token activates an account in one audited transaction. `SecretDetailsController` asks `SecretAccessHandler`, records `Viewed` only after allow, and calls `RevealAsync` only after a later allow. The Public API reaches `SecretsApiController` through the API key handler and uses the same policy. `AuditController` is `AdminOnly`.

`AngularUiRoutes` Angular-ის დოკუმენტს მხოლოდ თავის სიაში მოცემულ მისამართებზე აწვდის, შესვლის გვერდების ჩათვლით. შესულ მომხმარებელს გვერდის უცნობ მისამართზე `ServerPage`-ის „ვერ მოიძებნა“ გვერდი ხვდება. შესვლა `AuthController`-სა და `PendingSignInController`-ს იძახებს, ხოლო `SessionIssuer` სესიას მხოლოდ მეორე ფაქტორის შემდეგ გასცემს. მოწვევის ტოკენი ანგარიშს ერთ აუდიტირებულ ტრანზაქციაში ააქტიურებს. `SecretDetailsController` ეკითხება `SecretAccessHandler`-ს, `Viewed`-ს მხოლოდ ნებართვის შემდეგ წერს და `RevealAsync`-ს მხოლოდ მომდევნო ნებართვის შემდეგ იძახებს. საჯარო API `SecretsApiController`-ს API გასაღების დამმუშავებლით აღწევს და იმავე წესს იყენებს. `AuditController` `AdminOnly`-ა.

4. Focused code: reveal / გახსნის კოდი

svg/04-reveal.svg

Opening the details page checks access before it commits `Viewed`. Reveal checks access again, commits `SecretRevealed`, and only then calls `UnsealAsync`. The Angular page shows the plaintext once.

დეტალების გვერდის გახსნა წვდომას `Viewed`-ის დაფიქსირებამდე ამოწმებს. გახსნა წვდომას თავიდან ამოწმებს, აფიქსირებს `SecretRevealed`-ს და მხოლოდ შემდეგ იძახებს `UnsealAsync`-ს. Angular-ის გვერდი ღია ტექსტს ერთხელ აჩვენებს.

5. Deployment / განთავსება

svg/05-deployment.svg

Development and production are deployment nodes. Development runs Web on the developer machine and PostgreSQL in the Compose project. The reference production deployment runs Caddy, the vault image, and PostgreSQL on one Docker host: Caddy obtains the certificate, the vault trusts forwarded addresses only from Caddy's fixed address, and the database sits on an internal network. The demonstration is one disposable Development run, not another deployment.

Development და production განთავსების კვანძებია. Development Web-ს დეველოპერის მანქანაზე უშვებს, PostgreSQL-ს კი Compose პროექტში. production-ის საცნობარო განთავსება Caddy-ს, საცავის იმიჯს და PostgreSQL-ს ერთ Docker ჰოსტზე უშვებს: Caddy სერტიფიკატს თვითონ იღებს, საცავი გადაგზავნილ მისამართებს მხოლოდ Caddy-ის ფიქსირებული მისამართიდან ენდობა, ბაზა კი შიდა ქსელშია. დემონსტრაცია Development-ის ერთი ერთჯერადი გაშვებაა, არა სხვა განთავსება.

EclipsVault diagrams / დიაგრამები

Printable copy of the five C4 pictures in diagrams.md. Colours and type follow Pele's CSS variables. This page does not show a running vault.

diagrams.md-ის ხუთი C4 სურათის საბეჭდი ასლი. ფერები და შრიფტი Pele-ის CSS ცვლადებს მიჰყვება. ეს გვერდი გაშვებულ საცავს არ აჩვენებს.

1. Context / კონტექსტი

svg/01-context.svg

EclipsVault is one software system. A vault account in a browser is a person and uses a session. An application that uses a service account is an external system and calls the Public API with an API key. The identity provider, SMTP, and Vault Transit exist only when that integration is configured.

EclipsVault ერთი პროგრამული სისტემაა. ბრაუზერში მყოფი საცავის ანგარიში პიროვნებაა და სესიას იყენებს. აპლიკაცია, რომელიც სერვისის ანგარიშს იყენებს, გარე სისტემაა და საჯარო API-ს API გასაღებით იძახებს. იდენტობის მომწოდებელი, SMTP და Vault Transit მხოლოდ მაშინ არსებობენ, როცა ეს ინტეგრაცია კონფიგურირებულია.

2. Container / კონტეინერი

svg/02-container.svg

The Angular UI, the Web application, and one database are runtime containers. Redis is a fourth container only when it is enabled. The Angular UI runs in the browser and calls the UI API with the session cookie. The Web application serves the Angular files, the UI API, the Public API, and the Legacy pages that remain. The person and the external systems stay outside the boundary.

Angular UI, Web აპლიკაცია და ერთი ბაზა გაშვების კონტეინერებია. Redis მეოთხე კონტეინერია მხოლოდ მაშინ, როცა ჩართულია. Angular UI ბრაუზერში ეშვება და UI API-ს სესიის ქუქით იძახებს. Web აპლიკაცია Angular-ის ფაილებს, UI API-ს, საჯარო API-ს და დარჩენილ Legacy გვერდებს აწვდის. პიროვნება და გარე სისტემები საზღვრის გარეთ რჩებიან.

3. Web component / Web-ის კომპონენტი

svg/03-web-component.svg

The vault account reaches the Angular files, the Legacy pages, and the UI API. The UI API arrow ends at cookie authentication and does not call `SecretsController`, because the secret pages are not Angular routes yet. The Legacy pages reach `SecretsController` through that cookie authentication. The Public API reaches `SecretsApiController` through the API key handler. That controller asks `SecretAccessHandler`, and `SecretAccessPolicy` only answers allow or deny. After allow, `SecretsApiController` calls `RevealAsync`, as `SecretsController` does. SecretService and AuditSink persist through EF Core to the database outside the Web application.

საცავის ანგარიში აღწევს Angular-ის ფაილებს, Legacy გვერდებს და UI API-ს. UI API-ს ისარი ქუქის ავთენტიფიკაციაზე ჩერდება და `SecretsController`-ს არ იძახებს, რადგან საიდუმლოს გვერდები ჯერ Angular-ის მარშრუტები არ არის. Legacy გვერდები `SecretsController`-ს იმ ქუქის ავთენტიფიკაციით აღწევენ. საჯარო API `SecretsApiController`-ს API გასაღების დამმუშავებლით აღწევს. ეს კონტროლერი `SecretAccessHandler`-ს ეკითხება, და `SecretAccessPolicy` მხოლოდ უფლებას ან უარს პასუხობს. უფლების შემდეგ `SecretsApiController` იძახებს `RevealAsync`-ს, როგორც `SecretsController`. SecretService და AuditSink მონაცემებს EF Core-ით წერენ ბაზაში, რომელიც Web აპლიკაციის გარეთ დგას.

4. Focused code: reveal / გახსნის კოდი

svg/04-reveal.svg

`SecretRevealed` is committed before `UnsealAsync`. The earlier `Viewed` row is the details load, and it is written before the access decision.

`SecretRevealed` ფიქსირდება `UnsealAsync`-მდე. უფრო ადრეული `Viewed` დეტალების ჩატვირთვაა და წვდომის გადაწყვეტამდე იწერება.

5. Deployment / განთავსება

svg/05-deployment.svg

Development and production are deployment nodes. Development runs Web on the developer machine and PostgreSQL in the Compose project, because that project's `db` service is PostgreSQL. Production runs the Web image on a Docker host behind a TLS reverse proxy, and its database node may be PostgreSQL or SQL Server. The demonstration is one disposable Development run, not another deployment.

Development და production განთავსების კვანძებია. Development Web-ს დეველოპერის მანქანაზე უშვებს, PostgreSQL-ს კი Compose პროექტში, რადგან ამ პროექტის `db` სერვისი PostgreSQL-ია. Production Web იმიჯს Docker ჰოსტზე უშვებს TLS შებრუნებული პროქსის უკან, და მისი ბაზის კვანძი შეიძლება იყოს PostgreSQL ან SQL Server. დემონსტრაცია Development-ის ერთი ერთჯერადი გაშვებაა, არა სხვა განთავსება.
